# SPEC-004 physical iPad observations

Tested on 2026-10-14 around 19:29-19:39 America/Toronto, using Device Hub
connected to a physical iPad Air (5th generation), iPadOS 27.0.1.

## Candidate and scope

Native Reader S004 0.1.0 (5), source commit
`9cfd3b4bd66c93905ddb032f2db29b3ca9dc6df4`. The device engine came from C1 run
[38653003331](https://github.com/austery/legado/actions/runs/38653003331), whose
merge checkout and candidate have identical complete Git tree
`b8f3065b0dabf33403e9b344d84e068455482bbf`. The device app build succeeded;
AltStore signed and installed it over the prior native test app.

These are observations of that candidate, not acceptance of later revisions.
The original Wanyuan app was not replaced. Four existing source records were
preserved, three enabled. The 66-source bundle was not imported or certified.

## Observed interaction

- Default scope displayed all three enabled text sources. A repeated search for
  `天元珠` showed results while progress was still 2/3, with two discovered
  sources and two candidates for the work.
- An actual Device Hub tap expanded the rendered work row. It displayed
  `顶点小说⑤` and `爱下书小说网`, with their exact book URLs.
- Selecting the Aixiashu candidate loaded details, catalog and the first chapter's
  Chinese body. Next opened the second chapter and displayed its body.
- Selected scope with zero sources cleared results and disabled Search. Selecting
  Dingdian alone completed 1/1 with one source/candidate. All-enabled scope was
  restored afterward.
- Read-only comparisons of app-data backups before update, after update and after
  testing found the original shelf identity/source/chapter fields, full native
  resume row and source identity/enabled fields unchanged. No candidate was
  added to the shelf.

## Remaining acceptance gaps

A large remote touch drag in the first Aixiashu chapter left the body viewport
blank; a reverse drag remained blank. The title and controls stayed visible.
Next displayed the second chapter normally. The cause is undiagnosed: this has
not been independently reproduced with finger input or compared against C3 on
that physical device. Reliable continuous reading is not accepted.

A Stop tap raced normal completion, so it supplies no successful physical Stop
assertion. Expansion and candidate selection were observed, but were not proven
to occur while a peer remained in flight. Physical paging/retry/restart,
rotation, split view, offline restart and interactive shelf-resume acceptance
remain unverified. Data preservation is narrower than a complete resume journey.

This addresses the missing direct expansion and basic device-interaction evidence
in PR #16 review L16-S01, while leaving overall device acceptance partial.
Private app-data backups and the unsigned IPA remain local; no cloud delivery
was authorized. No private device identifiers or database contents are published.

## Follow-up: physical overscroll diagnosis and build 7

Later on 2026-10-14, PR #16 merged as
`8fd9921c43e537f2e8d9a0a4f80c8b2399de901a`; its merged-main
[C1 run](https://github.com/austery/legado/actions/runs/38656632711) passed.

The blank viewport was reproduced through Device Hub on the physical iPad.
A diagnostic build recorded only scroll geometry for the existing Dingdian
shelf book's first chapter: content height 5855 points, viewport 620 points,
normal maximum offset 5235 points, but a fast drag reached offset 14305.5.
The viewport was entirely past the body and later sprang back to 5235.
This establishes overscroll for the reproduced transient blank, rather than
missing chapter content. It does not characterize every possible blank screen.

Build 7 changes only the reader's scroll configuration: `bounces = false`,
replacing `alwaysBounceVertical = true`. Chapter edges now stop without elastic
bounce. Text, storage, and resume algorithms are unchanged. Temporary geometry
logging and exploratory test probes were removed before this build.

Native Reader S004 0.1.0 (7) was built from merged commit `8fd9921c4` plus this
ReadingText change, using the device engine from the successful merged-main C1.
The device build and IPA structure validation passed. AltStore updated the
existing native test app; device app inventory confirmed build 7. The original
Wanyuan app was not replaced. A full native-app data backup preceded diagnostics.

Physical checks through Device Hub in landscape:

- First Dingdian chapter: two large reverse drags and two large forward drags
  showed body text, including the exact gesture that produced the old blank.
- Next opened the second chapter with visible body text; the same large forward
  drag reached its end with text still visible.
- The existing shelf book remained available. These reading actions changed
  its reading position normally; unchanged resume data is not claimed here.

All 11 hosted ReadingRestorationTests and ReadingSaveCoordinatorTests passed
against the real engine. They cover restoration and save behavior, not the
physical fling regression. A programmatic simulator offset/pixel probe did not
reproduce the fault; an attempted hosted screen-capture probe was rejected by
the UI-testing permission boundary. Neither is reported as regression coverage.
The before/after physical gesture is the regression evidence. Independent finger
input, portrait/split-view coverage, and the remaining search acceptance gaps
above remain unverified. Private screenshots, backups, diagnostic trace and IPA
remain local; no cloud delivery was made.
