None were in `engine-ios/` or `native-ios-app/`.

| Area | Decision |

- Upstream `8c0b504d7` removed mbedTLS and stopped building `libmbedtls.a`.

  link `-lmbedtls`.
- Upstream U0..U1 added 14 whitespace errors (trailing spaces, blank lines at EOF) that
  fail the C1 `git diff --check` scope gate. `27df6e262` strips them in our fork instead
  of relaxing the gate. In `jsHelp.md` the two-space Markdown hard breaks became backslash
  hard breaks, which marked and the in-app renderer both support. A later upstream edit
  to the same lines can conflict; take upstream and strip the whitespace again.
- Test DB accessors implement upstream's new
  `AppDbAccessor.runInTransactionSuspending(onCommitted, block)` overload.

## Validation changes

`AutomaticImportFailureTest` now constructs the hook without arguments and expects
upstream's `NoStackTraceException`, which carries the injected cause message.
The test still requires: the failure reaches the caller, no row is written, and a
retry succeeds. No assertion, suite or timeout was removed.

## Review

Local Codex review (static, read-only) of the integration decisions found two P2 issues:

1. A reader source change that completed while no host was bound was logged and dropped.
2. `BookInfoRoute` bound the catalog callback and handler to the first `AppNavigator`.
   Android config rebuild replaces the navigator (`MainActivity` `rememberSaveable`) while
   `PageScreenModelHost` keeps the model. This existed before this integration.

`a1e5cddcd` keeps unpublished results in the model and publishes them on the next accepted
binding, and binds catalog sync per (model, navigator). A second Codex review found both
fixed and no new findings (`BLOCKING: no`). No dedicated test covers the host-rebuild
window; the result rests on static review plus unchanged suites.

## Recovery limits

U1 changes no Room schema or entity, so a code rollback to B stays schema-compatible.
Crypto now uses platform implementations and TXT/GBK charset handling uses the new
vendored charset module; a rollback restores old runtime behavior only.
No live provider, physical device, signing/distribution, Android, desktop or OHOS
acceptance is claimed.
