## Validation changes

Three `SearchModelSessionTest` cases asserted behavior that upstream changed. Per the owner's
decision they now assert the upstream behavior. No case was removed or skipped.

| Test | Old assertion | New assertion | Engine impact |
| --- | --- | --- | --- |
| `failedPageIsRetriedWithoutSkippingItsPageNumber` | A single-source failure cancels the round; searching again with the same id retries it. | The round finishes; `retrySource` retries. The page number is still not skipped (`[1, 1]`). | None. The engine calls `search` once and retries failed sources with `retrySource`. |
| `retryKeepsAcceptedPagesAndRetriesOnlyTheFailedPage` | Round signal `failed`. | Round signal `finished:false`. Kept pages and the retried page are unchanged. | None. The engine treats both round signals alike. |
| `queuedMainPagesKeepTheirOriginalGenerationWhileARestartRunsOutsideTheCap` (renamed) | A restart shares the main chain's page cap (peak 2). | A restart runs outside the cap (peak 3); queued main work still waits for a main slot; stale pre-restart work still fetches no second page. | A user restart of one source can add requests above the thread count. |
